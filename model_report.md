# Churn model -- selection and test results

Generated by `ModelTuning.py` from `model_tuning.toml`. All selection used 5-fold cross-validation on the 12,000-row training split only; the 3,000-row test split was scored once, by the winner.

## Selected model

**Gradient Boosting** (`sklearn.ensemble.HistGradientBoostingClassifier`)

- Cross-validated roc_auc: **0.97620**
- Hyperparameters: `class_weight=None, l2_regularization=5.0, learning_rate=0.05, max_features=0.6, max_iter=200, max_leaf_nodes=15, min_samples_leaf=80`
- Search: random over 48 configurations (240 fits, 187.6s)

> Histogram-based gradient boosting, the strongest single model measured on this
> data (5-fold CV AUC 0.97496 on the raw block, 0.97407 on the stage-1 CSVs) and
> by far the cheapest to fit here (~0.2s). Swap class_path to
> sklearn.ensemble.GradientBoostingClassifier for the exact-gradient-boosting
> variant -- it is ~7x slower and scored no better.

The model is saved with `pickle` as `churn_model.pkl`. The pickle holds the fitted estimator only -- no feature list, no config -- so the column order of `processed_train.csv` is part of the model's contract. Passing columns in a different order silently produces wrong scores, and passing a DataFrame makes scikit-learn warn that the estimator was fitted without feature names (it was fitted on a numpy array; pass a numpy array back).

## Caveats

- **This is a random-split score, not a temporal one.** Churn is ~0.23 for 2022/2023 signups but ~0.50 for 2024, and `signup_year` is among the features, so the model benefits from era information. Do not read this number as performance on future data; that needs a temporal holdout.
- **Selection used one CV pass, not nested CV.** The reported test score is unbiased because the test split was untouched, but the *CV* score is a mildly optimistic estimate of what the search would score on fresh data.
- Pinned to python 3.11.9, scikit-learn 1.9.1, numpy 2.4.6, pandas 3.0.6. A pickle will not load across incompatible versions.
- Re-running the module reproduces every number here. The estimator is seeded as well as the search, because an unseeded `HistGradientBoostingClassifier` varies run to run (`n_iter_` 185/190/182) and an unseeded forest resamples its bootstrap.
